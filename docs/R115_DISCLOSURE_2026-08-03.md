## 1. WHAT IS WRONG, IN ONE PARAGRAPH

Amendment **R115** registers `fitness.winner_max_fallback_frac: 0.10` — a search candidate may be
frozen as its arm's winner only if its authored reward actually ran, i.e.
`train_safe_default_count / train_safe_call_count < 0.10`. The **VALUE** is sound. What is wrong is
the **JUSTIFICATION** the frozen registration gives for it:

> *"THRESHOLD-INSENSITIVE, NOT TUNED: the observed distribution is strongly bimodal — worst trace
> 0.41 %, mildest severe 39.40 %, a **96× EMPTY GAP** — so any value in ~1–35 % partitions the data
> identically; 0.10 sits in that gap."*

That was true of RUN 1's 613 records. **It is a claim about a distribution, and the campaign has
since written thousands more candidates into it.** The gap has filled. An examiner who re-derives
the distribution — and Dr Okhrati is exactly that reader — finds the frozen document asserting
something its own data contradicts.

### 2.4 Where the sensitivity lives, and why that is coherent

All winner variation is confined to `qwen3_5_9b` — the **deliberately weakest capability anchor**
(86.00 % per-slot authoring loss; `docs/ops/authoring_reliability.py`). That is not a coincidence to
be explained away: an arm in which almost every candidate fails is precisely where a
marginally-executing candidate becomes the argmax. **The sensitivity is a symptom of the very
bottleneck the study was designed to measure.**

## 3. WHY THIS IS **NOT** A FORKING PATH — the four defences, each checkable

1. **CHRONOLOGY — and there is a far stronger form of this argument than the timestamps.**
   The value was committed at `b9c2be54`, **2026-07-28 15:17:05Z**, and frozen as v2.1
   (`3ca6f01ab772`) at **15:17:19Z**; the earliest artifact anywhere in the RUN 4 search tree is
   **2026-07-29T01:39:06Z**, and all 21 in-band candidates fall 07-29 → 08-02.
   **★ THE DECISIVE EVIDENCE DOES NOT DEPEND ON TIMESTAMPS AT ALL.** An auditor re-measured the
   surviving RUN 1 archive — the data that actually existed when 0.10 was chosen — and got
   **worst trace 0.41250 %, mildest severe 39.40200 %, and ZERO candidates in [1 %, 35 %]**. Those
   reproduce the registration's own quoted figures (0.41 % / 39.40 %) **exactly**. So the gap really
   was empty on the evidence available, and **there was no in-band datum in existence to tune 0.10
   to.** Use this rather than the mtime argument; mtimes in that archive are bulk-restamped to
   2026-08-01T01:52 and will not support a chronology claim.
   **⚠ Disclose one arithmetic discrepancy before an examiner finds it:** the registration says
   *"613 counter-carrying records"*; the surviving RUN 1 archive today holds **827** (it was pulled
   further before being discarded). Phrase it as *"613 as measured on 2026-07-28; the surviving
   archive now holds 827, still with zero in-band."* The gap claim is unaffected.
2. **MECHANISM — and phrase this precisely, because the loose version is snappable.** The
   **ELIGIBILITY FILTER** is effect-blind by construction: `scripts/run_campaign.py::_winner_eligible`
   (777-780) and `_fallback_frac` (764-774) read `train_safe_default_count` and
   `train_safe_call_count` and **nothing else**, enforced by a source-inspection test at
   `tests/test_winner_eligibility_floor.py:128-140` which asserts that `val_fitness`, `test_sharpe`,
   `test_cvar` and `fitness` never appear in either function's source. **Do NOT write "the rule is
   effect-blind"** — `select_winner:737` does read `val_fitness`, because it is the argmax. The
   correct sentence is: *the eligibility filter is effect-blind by construction; the argmax it feeds
   is the pre-existing registered selection rule, unchanged by R115.*
3. **SCOPE.** Zero effect on the confirmatory node (§2.3).
4. **COMMON-MODE.** The floor applies identically to every arm of every leg, so it cannot
   differentially advantage one side of any contrast.

## 4. WHY A **LIMITATION** AND NOT AN AMENDMENT — the constraint that decides it

An amendment row is the protocol for a design change. **It is unavailable here, and the reason is
mechanical rather than a matter of taste:**

* `PREREGISTRATION.md` **and** `config/preregistration.yaml` are both inside the frozen canonical
  hash **`3ca6f01ab772`**. Editing either moves the hash.
* The hash is an enforced live invariant: `enforce_freeze` refuses launches against a mismatch, it
  is a `session_preflight` check, and it is stamped into per-record provenance. **Moving it during a
  live, irreplaceable, un-rerunnable campaign is exactly the class of irreversible action that must
  not be taken** — and R115 itself required an unfreeze→amend→re-freeze cycle when it was created,
  which was legitimate only because zero campaign data existed at that moment.
* **The governing precedent is ADR-058b / execution record §90.** `PREREGISTRATION.md:3` still reads
  *"PRE-FREEZE … awaiting pilots"*, which is false and is inside the hash. The ruling there was
  explicit: **do not edit the frozen file; state the correction in the paper.** This is the same
  situation and takes the same remedy.

**⛔ AND THE THRESHOLD ITSELF MUST NOT BE CHANGED (see also §8 on prior art).** Changing a frozen value so that it matches data
observed afterwards is the post-data forking path the entire pre-registration exists to forbid. It
would convert a presentational defect into a genuine one.

**⛔ A "SENSITIVITY ANALYSIS" IS ALSO REFUSED, AND THIS SHOULD BE STATED SO NOBODY PROPOSES IT
LATER.** Reporting "what the result would have been under a different threshold" would require
training the alternative winners on the **sealed** test leg. Those rewards were never the registered
winners, so that is not a robustness check — it is a **new evaluation on sealed data by candidates
the registration never admitted**, i.e. a design change and a second look. It is not available.

**Winner-eligibility floor: the registered rationale, corrected.** Amendment R115 requires a search
candidate to have executed its authored reward on at least 90 % of its training steps before it may
be frozen as its arm's winner. The threshold (10 %) was fixed on 28 July 2026, before any candidate
of the reported campaign existed, and the rule reads only execution counters — never a performance
quantity — so it is effect-blind by construction and cannot have been chosen to favour an outcome.

The registration additionally argued that the specific value was immaterial, because the
then-available candidates were sharply bimodal and any threshold between roughly 1 % and 35 %
would partition them identically. **On the completed campaign that argument no longer holds, and we
state so rather than let it stand.** Of 1,520 search candidates, 21 fall inside that band, and for
two of the sixty (leg, arm) selection groups the choice of threshold within it determines which
reward is frozen. Both are on the `qwen3.5-9b` leg — the deliberately weakest member of the
capability ladder, whose authoring-failure rate is 86 % — which is where a marginally-executing
candidate is most likely to be the best-scoring one available.

Three things bound the consequence. First, the **confirmatory analysis is untouched**: no candidate
authored by the confirmatory model fell back on a single training step, so the floor never excluded
anything on that line and no threshold in any range would alter its winners. Second, the affected
leg is **report-only**, entering the pooled cross-model bound and the capability gradient rather than
the pre-registered confirmatory tests. Third, the floor is **common-mode** across every arm, so it
cannot differentially advantage either side of a contrast.

We have deliberately **not** revised the threshold. Amending a pre-registered value to fit data
observed after the fact is the practice pre-registration exists to prevent; the value stands as
registered and what is corrected here is only the argument originally offered for it. For the same
reason we do not report an alternative-threshold sensitivity: evaluating the counterfactual winners
would require exposing the sealed test leg to rewards the registration never admitted.

## 6. HONEST RESIDUALS — state these, do not bury them

* **The registered value is not the most conservative choice available inside the band.** For
  `qwen3_5_9b/distributional`, any threshold in [1 %, 7.85 %] would have **excluded** the candidate
  that 0.10 admits. The frozen value is therefore the more permissive option for that arm. This
  should be said plainly; spinning it would be worse than the defect.
* **The affected leg is report-only but not irrelevant.** Under R101 the legs feed the pooled
  cross-model bound and the R87 capability gradient, both of which are reported. A different frozen
  winner on `qwen3.5-9b` would move those numbers.
* **The provenance gap.** The 56 frozen-winner markers carry no execution-quality counters, so the
  eligibility fact is reconstructible only from the source search record. Recorded already in the
  standing disclosures; it is why `r115_threshold_sensitivity.py` joins on `candidate_id`.

## 9. METHOD NOTES FOR WHOEVER RE-RUNS THIS

* **Read the REAL exit code.** `python …r115_threshold_sensitivity.py | tail` reports `tail`'s
  status, not the script's. Redirect to a file and read the file. (The real exit here is **1** =
  claim falsified.) This repo has been bitten by a piped exit code before.
* **The positive control is not optional.** If `frozen arms joined` and `reproduced exactly` are not
  equal, every other number on the page is void — the script's model of the selection rule is wrong.
* **Three known, currently-unreachable divergences from production**, recorded so nobody re-discovers
  them as bugs: `winner_at` returns `None` on an empty eligible set where production raises
  `NoEligibleWinnerError` (unreachable — every one of the 60 groups contains a `frac = 0.0`
  candidate); `val_fitness` `None`-handling differs (moot — all 1,520 are floats, zero ties); and
  production's `select_winner:737` uses `r.get("metrics", {})` where `_fallback_frac:766` uses
  `... or {}`, so a `"metrics": null` record would crash the former (zero such records exist).
* **The auditor's decisive cross-check, worth repeating:** import `scripts/run_campaign.py::select_winner`
  and run the PRODUCTION selector over all 60 arm roots. Result 2026-08-03: **0 record-set diffs,
  0 winner diffs** against this instrument, and **56/56** against the frozen markers. That is the
  strongest available evidence that the re-derivation is faithful.
